# Changelog

## Unreleased — verified fixes (2026-09-06)

The Builder's Live Preview panel never actually rendered anything: `renderPreview()`
was called from ~15 places in `workbook-studio.js` but the method itself was never
defined, so every Builder edit silently threw and `#wb-preview` stayed empty. This
was the root cause of every bug reported against v1.2:

- **Second/third worksheet tabs were not clickable** — there was nothing real in
  Live Preview to click. The actual runtime (`lms-workbook.js`) already used
  explicit `data-workbook-tab-index` correctly; the Builder just never mounted it.
- **PDF fields were not fillable when tested in Preview** — same cause. Real
  AcroForm text/dropdown/radio/checkbox/option-list fields are correctly created
  by `generatePDF`, confirmed by loading the generated bytes back through pdf-lib.
- **Uploading a filled PDF did not populate the HTML** — `importPreviewPDF`
  referenced `this.previewRuntime`, which was always `null` because nothing ever
  assigned it.

Fixed by implementing `renderPreview()`: it regenerates the workbook HTML, mounts
a real `LMSWorkbook` runtime instance into `#wb-preview` under an isolated
`preview:<id>` storage key, and rewires the preview's own upload/download buttons
to go through the Studio's in-browser PDF generation/import (so preview doesn't
require a hosted PDF asset URL).

Verified end-to-end in a real browser (not just code review):
- Added a 2nd worksheet, clicked its tab, confirmed the correct worksheet became visible.
- Filled a field, downloaded a PDF, inspected it with pdf-lib and confirmed a real
  `PDFTextField` (and `PDFDropdown`/`PDFRadioGroup`/`PDFCheckBox`/`PDFOptionList`
  for the other field types) with the typed value present.
- Reset the form, re-uploaded that PDF, confirmed the field repopulated and persisted.
- Loaded the actual `sample_partially_filled_progress.pdf` shipped in this repo
  against a matching legacy-schema model and confirmed all 5 answered fields
  imported correctly via the old `Worksheet N::Section::Field` naming.
- Confirmed collapsible sections and multi-column section layout render and toggle
  correctly in the live preview.

Also fixed:
- `index.html` (the file GitHub Pages serves by default) was missing the
  `fontkit` and `lms-workbook.js` `<script>` tags that `studio.html` had, so a
  fresh Pages deploy would silently lose Live Preview and custom PDF font
  embedding. `index.html` is now identical to `studio.html`.
- `auto-test.html`, a self-check harness that was written but never actually run,
  assumed the default section was collapsible and threw on `null.click()`,
  hanging forever. Fixed so it completes and all assertions pass.
- Exposed the Studio instance as `el.__studio` and the preview runtime as
  `previewRoot.__lmsWorkbook`, matching the convention already used elsewhere,
  so the instances are introspectable for testing.
- Removed `runtime-demo.html` and `production-snippet.html`: both referenced an
  abandoned `LMSWorkbook.mount(root, config)` API and CSS classes the current
  runtime no longer emits, so they were broken examples rather than working ones.

## v1.2

1. Added collapsible sections with configurable default-open state.
2. Added 1/2/3-column section layouts.
3. Added per-question column assignment.
4. Added section image blocks with URL, alt text, width and column.
5. Added corresponding HTML and PDF layout support.
6. Reworked PDF import matching to support stable field IDs plus legacy field names, including `long`, `date`, `text`, and `needs` naming conventions.
7. Confirmed uploaded answers are merged into the existing form; blank uploaded fields are ignored.
8. Fixed long and short text PDF generation to create real text form fields and make long text multiline.
9. Improved collapsible-section initial state and worksheet-tab binding.
10. Added end-to-end logic tests covering HTML generation, worksheet tabs, columns, collapsible sections, legacy PDF field matching and PDF text-field creation calls (this test existed but was never actually executed until the fix above — see Unreleased).

## v1.1

- Fixed generated PDF short-text, long-text, date, number and other text-backed fields: they are now actual PDF form fields placed over the designed response boxes.
- Long-text PDF fields are multiline.
- Worksheet tabs now carry an explicit worksheet index and the runtime uses that index when switching tabs.
- Preview now uses a dedicated local-storage namespace (`preview:<workbook-id>`) instead of sharing the student LMS namespace.
- Preview PDF import now persists imported answers to IndexedDB/localStorage through the runtime, then reflects them in the existing HTML form.
- PDF import matching is more tolerant: stable generated field IDs are preferred, legacy worksheet/section/label names remain supported, and a unique question-label fallback is supported for older PDFs or renamed sections.

## v1.0

- Restored full styling for the Workbook Builder authoring interface.
- Fixed backwards-compatible Preview PDF import for older field naming used by earlier prototypes, including text, date, dropdown, radio and checkbox-group fields.
- PDF import now distinguishes between a PDF with no answers and a PDF that contains answers but does not belong to the current workbook definition.

## v0.9

- Fixed PDF import in Builder Preview and LMS runtime to support current field IDs plus legacy semantic field names.
- Upload now merges only answered PDF fields; blank fields never erase existing HTML answers.
- Checkbox groups, radio groups, dropdowns, option lists and text fields are imported through the matched PDF field name.
- Generated LMS HTML remains HTML-only, with no script/link tags.
